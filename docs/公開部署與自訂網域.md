# 公開部署與自訂網域

## 目前狀態

- 網站是 Vite 靜態輸出，執行 `pnpm build` 後會產生 `dist/`。
- 專案會在建置時為首頁、`/profile/`、`/evidence/`、`/en/` 與 38 件專案輸出獨立的靜態 HTML，因此 GitHub Pages 可以直接開啟各頁網址。
- 已加入 GitHub Pages workflow、`robots.txt`、網站 manifest、`sitemap.xml`、canonical、頁級 Open Graph 與 Twitter 分享 metadata。
- GitHub repository、`main` 分支與 GitHub Pages 已建立；公開網址為 `https://daniel-tsai-9487.github.io/`。
- 本輪最新進度與證明頁變更目前只在本機工作樹，尚未 commit、push 或部署。尚未購買／綁定自訂網域，也未設定自訂 DNS。

## 建議路徑

目前使用 GitHub Pages 與 `.github/workflows/deploy-pages.yml`。若未來希望將 DNS、SSL 與靜態託管集中管理，Cloudflare Pages 仍可作為替代方案，但不需要為本輪內容更新切換平台。

## 需要使用者確認的資訊

1. 是否要繼續使用 `daniel-tsai-9487.github.io`，或改用完整自訂網域。
2. 若改用自訂網域：網域註冊商、DNS 管理位置與完整 FQDN。
3. 是否要將自訂網域版本交由搜尋引擎收錄。

## GitHub Pages 發布流程

1. 先在本機確認本輪內容，再由使用者決定是否 commit 與 push；本文件本身不授權自動發布。
2. 推送至 `main` 後，既有 workflow 會安裝依賴、執行 `pnpm build`，並把 `dist/` 發布到 Pages。
3. 若啟用自訂網域，在 Pages 的 Custom domain 欄位填入確認過的 FQDN，再依 GitHub 顯示的 DNS 記錄到網域註冊商設定。
4. 建立 `public/CNAME`，內容只放完整 FQDN；再將 `src/site.ts` 的 `origin` 改為該 HTTPS 網址後重新部署。建置會同步更新 canonical、Open Graph URL 與 `sitemap.xml`。

## Cloudflare Pages 替代流程

1. 將已推送的 GitHub repository 連接至 Cloudflare Pages。
2. Build command 設為 `pnpm build`，output directory 設為 `dist`。
3. 在 Pages 的 Custom domains 設定確認過的網域，依介面指示完成 DNS 與 SSL。
4. 網域可用後，再填入 canonical、Open Graph URL 與 sitemap。

## 公開前內容檢查

- 保留目前每案的 `publicScope`、`PUBLIC SYNTHESIS`、`RECORD ONLY` 與 `RESTRICTED` 邊界。
- 不把醫療原始資料、企業 URS／客戶文件、金融資料、私有 repository、帳號、環境變數或未取得授權的圖片放入 repository。
- 將現有的 GitHub、Facebook、Instagram 連結視為公開個人入口；只有在確認可長期公開後才新增電子郵件或其他聯絡方式。
