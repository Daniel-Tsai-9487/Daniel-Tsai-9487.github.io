# 公開部署與自訂網域

## 目前狀態

- 網站是 Vite 靜態輸出，執行 `pnpm build` 後會產生 `dist/`。
- 專案會在建置時為首頁與 34 件專案輸出獨立的靜態 HTML，因此 GitHub Pages 可以直接開啟 `/projects/<project-id>/`。
- 已加入 GitHub Pages workflow、`robots.txt`、網站 manifest、`sitemap.xml`、canonical、頁級 Open Graph 與 Twitter 分享 metadata。
- 已在本機建立 `main` 分支 Git repository；尚未建立 commit、設定遠端、啟用託管平台、購買或綁定網域、設定 DNS。

## 建議路徑

首選是 GitHub Pages：目前已有公開 GitHub 個人頁面，且專案已備妥 `.github/workflows/deploy-pages.yml`。若希望將 DNS、SSL 與靜態託管集中管理，Cloudflare Pages 也適合這個純靜態網站，但目前沒有預設採用任何平台。

## 需要使用者確認的資訊

1. 要使用的完整網域，例如 `your-name.tw` 或 `portfolio.your-name.tw`。
2. 託管平台：GitHub Pages 或 Cloudflare Pages。
3. 網域註冊商與 DNS 管理位置，以及是否要將網站交由搜尋引擎收錄。
4. 若使用 GitHub Pages：目標 GitHub repository，以及是否使用 `Daniel-Tsai-9487.github.io` 作為過渡網址或正式根網址。

## GitHub Pages 發布流程

1. 在 GitHub 建立目標 repository，將目前本機的 `main` 分支建立首次 commit 後推送至遠端。
2. 在 repository 的 Pages 設定中選擇 `GitHub Actions` 作為來源。
3. 推送後，workflow 會安裝依賴、執行 `pnpm build`，並把 `dist/` 發布到 Pages。
4. 在 Pages 的 Custom domain 欄位填入確認過的 FQDN，再依 GitHub 顯示的 DNS 記錄到網域註冊商設定。
5. 建立 `public/CNAME`，內容只放完整 FQDN；再將 `src/site.ts` 的 `origin` 改為該 HTTPS 網址後重新部署。建置會同步更新 canonical、Open Graph URL 與 `sitemap.xml`。

## Cloudflare Pages 替代流程

1. 將已推送的 GitHub repository 連接至 Cloudflare Pages。
2. Build command 設為 `pnpm build`，output directory 設為 `dist`。
3. 在 Pages 的 Custom domains 設定確認過的網域，依介面指示完成 DNS 與 SSL。
4. 網域可用後，再填入 canonical、Open Graph URL 與 sitemap。

## 公開前內容檢查

- 保留目前每案的 `publicScope`、`PUBLIC SYNTHESIS`、`RECORD ONLY` 與 `RESTRICTED` 邊界。
- 不把醫療原始資料、企業 URS／客戶文件、金融資料、私有 repository、帳號、環境變數或未取得授權的圖片放入 repository。
- 將現有的 GitHub、Facebook、Instagram 連結視為公開個人入口；只有在確認可長期公開後才新增電子郵件或其他聯絡方式。
